2026-10-28에는 앱 기능 메타데이터를 영속 `logseq/metadata.sqlite`로 분리하고 bilog2에서 검증했다. 이 저장소는 재생성 가능한 ID 캐시와 다르며 보존해야 한다. 기능 기록에 연결된 ID의 복구·외부 편집 대응도 보강되었으므로, 아래 초기 S01-B의 일괄 ID 재생성 설명보다 [메타데이터 저장·복원 정책](validation/s01-metadata-audit.md)이 최신 구현을 설명한다. ## 1. 이관 원칙

기능과 사용 흐름을 가져오되 Swift 코드를 그대로 옮기지 않는다. OG의 블록 식별자, 참조, 쿼리, 저장 및 편집 구조를 활용해 변경 범위를 줄인다.

- OG 기본 기능은 재구현하지 않고 실제 사용 검수 후 부족한 차이만 수정한다.
- bilog 구현 기능과 아직 구현하지 않은 요구사항을 분리한다.
- 저장 형식은 아래 확정 원칙을 따른다. OG 기본 저장 방식을 무조건 우선하지 않는다.
- 기본 편집기는 최대한 유지하고, 파일 저장 경계에는 내부 ID 분리를 위한 변경이 필요하다.
- S01은 개발 빌드의 macOS 인수를 완료했으며 나머지 이관 항목은 미착수다. 기본 기능 재사용 항목은 검수 대상이다.

### S01. 내부 ID 외부 분리 — 재인터뷰 확정 요구사항

2026-10-27 재인터뷰 기준. Markdown을 문서 원본으로 유지하고 SQLite는 재생성 가능한 ID·대응 정보 캐시로 사용한다. 아래는 확정 요구사항이다. 구현 경과와 최종 인수 판정은 검증표 뒤에 기록하며 요구사항 자체를 축소하지 않는다.

#### S01-A. 원본·저장 위치·범위

- 새 그래프에서 시작한다. 기존 bilog/OG 문서 가져오기는 후속 작업이다.
- Markdown 본문·계층을 원본으로 삼고 내부 페이지·블록 ID 선언(`id:: UUID` 등)을 자동 기록하지 않는다.
- ID·문서 대응 정보는 그래프 안의 일반 폴더 `logseq/identity.sqlite`에 저장한다. 숨김 폴더를 사용하지 않는다.
- SQLite는 문서 본문 원본이나 유일한 충돌 복구본 저장소가 아니다. 문서 원본을 DB에 두는 Logseq DB 버전 및 단방향 Markdown 미러 방식으로 전환하지 않는다.
- 사용자 속성·태그·멘션은 별도 범위다. 모든 UUID 문자열을 제거하거나 기존 파일의 ID를 일괄 삭제하는 변환을 하지 않는다.
- 원본 OG와 같은 그래프를 번갈아 편집하는 호환성은 보장하지 않는다.

#### S01-B. ID 수명과 재생성

- 내부 편집·선택·관계 처리를 위해 실행 중 페이지·블록 ID를 사용하되 영구적으로 같은 ID를 보존할 의무는 없다.
- 유효한 캐시는 재사용할 수 있다. 외부에서 내용·순서가 변경된 문서는 블록 ID를 모두 재생성한다. 유사도 기반 블록 매칭은 구현하지 않는다.
- 해당 문서의 이전 커서·선택·undo를 초기화하고, 이전 ID가 새 문서나 다른 블록에 적용되지 않게 한다. 미저장 편집이 있으면 재파싱보다 충돌 보존·선택을 먼저 수행한다.
- SQLite 삭제·손상 시 Markdown을 보존한 채 자동 재생성하고 간단히 알린다. 재생성 승인이나 읽기 전용 대기를 요구하지 않는다.
- 파일 이름 변경·이동 식별과 링크 수정은 ID 영속성과 분리한다. 확실하게 식별될 때만 이전 문서와 연결하며, 모호하면 추측해서 연결하거나 링크를 수정하지 않는다.
- SQLite에 쓸 수 없는 권한·용량 오류는 삭제·손상과 구분한다. 이 경우 반복 재생성으로 정상 저장인 것처럼 처리하지 않는다.

#### S01-C. 문서 링크와 이름 규칙

- 문서 링크·문서 임베드만 지원한다. 블록 참조·블록 임베드·별도 블록 앵커는 제외하고 N04/N05 연결 이월도 보류한다.
- 기본 링크는 `[[회의]]`처럼 파일 이름을 사용한다. 동명 문서가 있을 때만 경로로 구분한다.
- 경로는 그래프 루트 기준이다. 예: `[[pages/업무/회의]]`. 링크가 위치한 문서나 임베드 위치에 따라 상대적으로 해석하지 않는다.
- 확장자는 기본 생략한다. 같은 경로에 확장자만 다른 문서 등 구분이 필요할 때 포함한다. 예: `[[pages/업무/회의.md]]`.
- 파일 이름과 문서 제목은 독립적이다. `회의.md`의 제목이 `주간회의`여도 파일 이름으로 참조하며, 제목 변경만으로 파일이나 링크를 바꾸지 않는다.
- 동명 파일이 나중에 추가되면 기존 대상에 경로를 붙이는 수정안을 안내하고 사용자 선택 후 반영한다. 수정 전에는 모호한 링크로 표시하며 임의 대상을 선택하지 않는다.
- 앱 안의 이름 변경·이동과 확실히 감지한 외부 이름 변경·이동 모두 관련 링크·임베드 수정안을 안내하고 사용자 선택 후 반영한다. 변경 전 대상을 입증할 정보가 없으면 수정안을 임의 생성하지 않는다.
- 없는 문서의 링크를 누르면 생성 위치를 보여주고 사용자 확인 후 생성한다. 기본 위치는 `pages/새 회의.md`이며 변경 가능하다.
- 외부에서 들어온 `((UUID))`, `{{embed ((UUID))}}`는 원문을 보존하고 실행하지 않으며 지원하지 않는 참조라는 안내를 표시한다. 자동 삭제하지 않는다.

#### S01-D. 문서 임베드

- 문서 임베드 안에서 바로 편집할 수 있다. 원본 Markdown과 같은 문서의 다른 표시 위치에도 변경을 반영한다.
- 문서 링크와 동일한 파일 이름·경로 해석 규칙을 적용한다.
- A → B → A처럼 순환하면 반복이 시작되는 지점에서 펼치기를 멈추고 원본 링크를 표시한다. 나머지 내용은 표시·편집할 수 있다.
- OG의 `{{embed [[문서]]}}`를 기반으로 한다. `![[문서]]` 별칭은 B08의 별도 범위이며 이번 인터뷰가 추가 구현을 확정한 것은 아니다.

#### S01-E. 충돌·삭제·복구

- 앱 미저장 편집과 외부 변경이 겹치면 양쪽 내용을 먼저 보존하고 비교 화면에서 앱 편집본 또는 외부 변경본을 선택한다. 직접 병합 편집 UI는 이번 범위에서 제외한다.
- 복구본은 그래프의 일반 폴더 `logseq/conflicts/`에 Markdown 파일로 저장한다. 일반 문서 검색·참조·임베드 대상에서 제외한다.
- 선택하지 않은 내용도 선택 전후 복구할 수 있다. 해결된 복구본도 사용자가 삭제할 때까지 보관하며 자동 삭제하지 않는다. 정리 기능은 후속 작업으로 둘 수 있다.
- 외부에서 파일을 삭제했는데 앱에 미저장 편집이 있으면 편집본을 먼저 보존하고 해당 문서 자동 저장을 멈춘다. 사용자가 '편집본으로 문서 복원' 또는 '삭제 유지'를 선택한다. 임의로 별도 문서를 만들지 않는다.
- 복구본 저장 실패 시 편집 상태를 지우거나 원본을 덮어쓰지 않는다. 재시작 후에도 저장된 충돌과 선택 상태를 확인할 수 있도록 한다.
- Markdown 저장과 SQLite 갱신 중 한쪽만 성공하거나 프로세스가 중단돼도, 실제 본문과 일치하지 않는 ID 캐시를 적용하지 않는다. ID 캐시 복구를 위해 Markdown을 이전 내용으로 되돌리지 않는다.

#### 이전 S01에서 대체된 결정

- 숨김 폴더의 ID 파일 → 일반 경로 `logseq/identity.sqlite`.
- 외부 수정 시 확실한 블록 ID 유지·모호한 블록만 재발급 → 변경된 문서의 블록 ID 전체 재생성.
- 재시작·이동 전후 동일 ID 보장 중심 → 실행 중 일관성과 유효 캐시 재사용 중심; 문서 링크는 ID와 독립.
- 블록 참조 표시, 경로·확장자·제목 규칙의 미확정 상태 → S01-C로 확정.
- 본문과 ID 파일의 공동 영속성 중심 → 본문 보존 우선, SQLite 캐시는 해시 검증 후 재구축 가능.

#### S01 구현 계획 — 1차 구현 착수, 전체 완료 전

아래 순서는 S01 내부의 의존 순서다. B/N 기능 전체의 우선순위 확정을 뜻하지 않는다. 제품 결정과 구현 선택을 구분하며, SQLite 드라이버·세부 스키마·장애 복구 방식은 실제 OG 런타임에서 검증한다.

1. **저장 경계와 참조 해석의 기초**
   - 원본 OG의 내부 UUID와 DataScript를 유지하고 SQLite ID 저장소를 분리한다.
   - `modules/file/core.cljs`, `handler/editor.cljs`, `fs/watcher_handler.cljs`의 ID 자동 기록 경로와 참조 생성 경로를 함께 점검한다. 문자열 정규식 일괄 삭제로 처리하지 않는다.
   - 문서별 실제 경로·표시 제목·참조 키를 분리한다. OG의 `:block/name`만 경로로 치환해 태그·별칭·namespace까지 바뀌지 않도록 경계를 설계한다.
   - `logseq/identity.sqlite`와 SQLite 부속 파일, `logseq/conflicts/`를 일반 문서 인덱싱에서 제외한다. 기존 `logseq/config.edn` 등 관리 파일 처리는 유지한다.
2. **SQLite ID 캐시**
   - 제안 스키마: 버전/파서 버전, 문서 상대 경로·페이지 UUID·원본 바이트 SHA-256·revision, 문서별 블록 순서·UUID. 블록 대응은 전체 본문 해시가 일치할 때만 사용한다.
   - 문서별 캐시 갱신은 SQLite 트랜잭션으로 처리하고 UUID 중복·불완전 레코드·지원하지 않는 스키마를 검증한다. 여러 창의 쓰기는 하나의 저장 담당 경로에서 직렬화한다.
   - 재생성 뒤 DB의 부모·앞 형제·소속 문서 관계, 캐시, 열린 임베드, 선택·undo를 함께 갱신한다. 페이지 ID 재발급 시에도 관련 조회 결과를 재계산한다.
   - SQLite 드라이버는 OG Electron 내장 Node와 배포 ABI에서 확인한다. DB 버전의 `node:sqlite` 사용 가능성을 OG에 그대로 가정하지 않는다.
3. **본문 저장과 충돌 복구**
   - 문서별 저장 큐에서 기준 디스크 해시, 현재 입력창을 포함한 앱 편집본, 외부 버전을 비교한다. 공백을 제거한 비교로 대체하지 않는다.
   - 본문 저장 성공 후 해당 해시의 SQLite 캐시를 확정하는 흐름을 우선 검토한다. SQLite만 실패하면 경고 후 캐시를 무효화하고 본문은 유지한다.
   - 복구본과 원래 경로·버전 해시·선택 상태를 기록하는 별도 manifest를 `logseq/conflicts/`에 두는 방안을 검토한다. 이 기록을 삭제 가능한 ID SQLite에만 의존시키지 않는다.
   - 임시 파일 교체, 저장 전 원문 보존, 오류 전달과 재시작 복구를 구현한다. 해시 확인과 파일 교체 사이 외부 쓰기 경쟁은 단순 rename만으로 해결됐다고 간주하지 않고 장애 테스트로 검증한다.
   - 한글 조합 중 편집 상태를 강제로 지우지 않으며, 외부 변경·삭제를 큐에 보관한 뒤 안전한 시점에 충돌 선택을 진행한다.
4. **외부 변경·문서 참조**
   - 시작 시 디스크 스캔과 watcher 이벤트를 같은 재조정 경로로 모은다. 본문 변경이면 문서 단위 ID 재생성, 미저장 상태면 충돌 처리를 먼저 수행한다.
   - 이름 변경·이동은 이벤트 묶음과 파일 식별 정보를 검토한다. 동일 내용 해시만으로 복사 후 삭제와 이동을 확정하지 않는다. 식별 불가 시 오연결하지 않는다.
   - 링크·임베드·자동완성에 공통 해석기를 적용하고, 동명 파일 발생 및 이름 변경의 수정 전후 미리보기를 제공한다. 사용자 선택 직전 원문 revision/hash를 재검사한다.
   - 링크 수정은 AST의 실제 링크·임베드 구간에 한정한다. 코드·일반 문자열은 보존하며 임베드 대상을 기존 백링크 목록에만 의존해 수집하지 않는다.
5. **사용자 흐름과 회귀 검증**
   - 없는 문서 생성 위치 확인, 비지원 블록 참조 안내, 앱/외부 버전 선택, 외부 삭제 복원 선택을 연결한다.
   - 임베드 편집은 원본 문서 저장 경로를 공유하고 순환 탐지는 현재 펼침 경로 기준으로 수행한다.
   - 블록 참조 명령·복사·붙여넣기·자동완성 및 PDF/플래시카드 등 간접 참조 생성 경로를 감사한다. 부가 기능 지원 범위가 달라지면 별도 결정으로 남긴다.

설계 당시 기술 검토 항목(아래 구현·검증 결과로 구체화): 지원 문서 확장자 범위, 대소문자/Unicode 충돌 규칙, 파일 이동 판별 증거, SQLite 호환성·스키마 교체 절차, 복구 manifest 및 디스크 동시 쓰기 보장 범위. 확정된 인터뷰를 반복하지 않고 구현 증거로 정하되 사용자 동작 범위가 바뀌면 별도 결정한다.

#### S01 1차 구현 기록 — 2026-10-27

Markdown 원본과 SQLite 캐시를 분리하는 저장 경계, 문서 참조 및 충돌 선택 흐름을 OG에 연결했다. 새로운 빈 데스크톱 그래프는 `logseq/config.edn`의 `:s01/enabled? true`로 활성화한다. 문서가 있는 기존 그래프를 자동 변환하지 않는다. 테스트는 매번 별도 임시 그래프와 임시 Electron 사용자 설정으로 실행했다.

- **저장·ID**
  - `src/electron/electron/s01.js`: Electron main의 동기 IPC 저장 담당, 내장 `node:sqlite`, SQLite 트랜잭션, SHA-256 원문 검증, UUID 중복·불완전 행·손상/미지원 스키마 복구.
  - 실제 스키마 v1: `documents(path, hash, page_id, block_ids)`와 이동 감지용 `inventory(path, file_key)`. 본문은 SQLite에 저장하지 않는다. 파서의 ID 배치 규칙이 바뀌는 후속 변경에서는 캐시 버전도 갱신해야 한다.
  - `graph-parser/extract.cljc`의 콜백으로 페이지·블록 ID를 주입한다. 외부 내용 변경은 전체 블록 ID를 새로 만들고, 같은 본문의 유효 캐시는 재사용한다. 다른 문서의 참조 페이지 UUID는 보존한다.
  - 자동 `id::` 기록을 막으며 사용자 원문의 UUID/속성을 일괄 삭제하지 않는다. 빈 Markdown도 페이지 식별 정보를 만들 수 있다.
- **충돌·외부 변경**
  - `logseq/conflicts/<UUID>/`에 `base.md`, `app.md`, `disk.md`와 해시·상태·선택을 가진 `manifest.json`을 기록한다. manifest를 마지막에 기록하며 복구본 저장에 실패하면 원본 교체를 중단한다.
  - 본문을 먼저 저장하고 ID 캐시를 후속 갱신한다. 캐시 갱신만 실패하면 본문을 되돌리지 않고 경고한다.
  - watcher 이벤트 처리 시 현재 디스크를 다시 읽는다. 해소된 충돌의 지연 알림을 무시하고, ID 세대가 바뀐 뒤 도착한 과거 저장 요청을 건너뛴다.
  - 해당 페이지의 undo/redo 항목을 제거한다. 다른 문서의 이력은 유지한다. OG의 전역 Undo는 다른 문서로 이동할 수 있으며, 이를 현재 문서의 내용 복원과 혼동하지 않도록 테스트했다.
  - 페이지 메뉴의 **저장 충돌 확인**에서 미해결 충돌을 다시 열 수 있다. 시작 시에도 저장된 미해결 목록을 확인한다.
- **문서 참조·화면**
  - `src/main/frontend/s01.cljs`: 파일 이름/루트 경로/확장자 해석과 기본 짧은 링크 선택. 제목은 `title::` 표시 속성으로 수정하고 파일 이름·이동은 별도 메뉴로 처리한다.
  - `src/electron/electron/s01_refs.js`: Mldoc 구간과 UTF-8 바이트 위치를 사용해 실제 링크·임베드 수정안을 만든다. 라벨·강조·코드 원문을 보존한다.
  - 동명 추가 및 입증 가능한 이동 시 파일별 수정 전후와 체크박스를 제공한다. 선택 전에는 링크 파일을 쓰지 않으며, 적용 직전 원문 해시를 다시 검사한다.
  - 외부 이동은 유일한 `device/inode/birthtime` 대응에 한정한다. 내용이 같은 복사본만으로 이동을 추측하지 않는다.
  - 없는 문서 생성 위치 확인, 문서 임베드 편집·순환 중단, 비지원 블록 참조 원문 표시를 연결했다. 블록 참조/임베드 생성 명령·복사 메뉴를 제한한다. 논리적인 태그·속성 참조를 삭제하지 않는다.

#### S01 후속 구현 및 검증 — 2026-10-27

기존 남은 조건에 따라 저장 경쟁·재시작 복구, 파일 식별과 참조 인덱스, 실제 편집 상태 추적, 저널 정리를 보강했다. 후속 실제 macOS 한글 입력 검증 결과를 아래에 추가했다. 개별 시나리오 통과를 모든 입력기·키 조합의 포괄적 보장으로 확대하지 않는다.

1. **저장 경쟁과 재시작 복구**
   - 기존 inode를 복구 디렉터리의 `displaced.md`로 옮긴 뒤, 새 본문은 배타적 hard link로 설치한다. 교체 직전 다른 파일이 나타나면 덮어쓰지 않고 충돌로 보존한다. 교체 직전 외부 버전도 UI에서 선택할 수 있다.
   - 기존 inode를 열어 둔 외부 프로그램의 늦은 쓰기를 복구본에서 감지하고 미해결 상태로 전환한다. 이는 보관된 inode의 변경 감지이며, 저장 종료 후 현재 원본에 일어나는 모든 외부 쓰기를 금지한다는 보장은 아니다.
   - `intent.json`으로 복구본 작성 도중 중단된 저장의 문서 경로와 해시를 남긴다. 완전히 기록된 앱 편집본은 재시작 시 복구 목록으로 복원한다. 앱 본문 자체가 아직 디스크에 기록되지 않은 시점의 강제 종료까지 복구할 수 있다고 주장하지 않는다.
   - 다른 창의 미해결 편집본을 하나의 선택으로 일괄 해소하지 않는다. 동일한 중복 충돌 알림은 합치고, 재검토가 필요한 이전 선택은 새 기록으로 연결한다.
   - S01에서는 renderer 간 미저장 DB 전송을 사용하지 않고 각 창이 파일 감시 이벤트와 저장 비교를 수행한다. 캐시 세대를 공유해 각 창이 캐시 재생성을 감지한다. 재시작 시에는 저장된 화면 캐시의 페이지·블록 ID를 SQLite와 비교해 불일치 문서만 다시 읽는다.
2. **파일 식별·참조 인덱스**

3. **편집 상태와 간접 기능**
   - 원문 직렬화 문자열 대신 저장된 블록 구조와 현재 구조를 비교한다. 입력 버퍼는 현재 DB 블록과 비교하므로 CRLF·일반 문단이나 이미 저장된 입력을 미저장으로 오인하지 않는다.

#### S01 최종 상태 — 개발 빌드 macOS 인수 완료

**2026-10-27 판정: S01 개발 빌드의 macOS 인수를 완료한다.** V14의 마지막 보류 항목은 사용자 물리 키보드 대조와 반복 조합·저장·재시작 검증으로 해소했다. 자모 분리는 자동화 입력 경로의 제약으로 분류하고 제품 코드에 추측성 IME 우회 처리를 추가하지 않았다. 이번 변경은 검증 스크립트·증거·문서다. 앞 절의 빌드·203 tests/1720 assertions·저장소 각 40개 및 UI 회귀 통과 결과는 유지하며, 이번에 전체 회귀를 재실행한 것으로 표시하지 않는다.

1. **`compositionend.isTrusted=false` 원인 확인 완료**
   - 실행 환경: Electron 41.7.1 / Chromium 146.0.7680.216. 앱 없는 순수 textarea에서 Chromium Input 프로토콜과 실제 macOS 두벌식 키 입력을 각각 시험했다. 두 경로 모두 시작·갱신은 true, 종료는 false였고 capture/bubble에서 동일했다.
   - 조합 동안 JavaScript `dispatchEvent` 호출은 **0건**이다. 이후 별도 숨김 입력칸의 의도적 합성 이벤트는 래퍼에 정확히 1건 기록되어 계측이 작동함을 확인했다. 프로토콜 시험을 실제 OS 입력기 시험으로 대체하지 않았다. 순수 대조 앱에는 Logseq·React·preload·Playwright가 없다.
   - 정확히 같은 Chromium 버전의 [InputMethodController](https://github.com/chromium/chromium/blob/146.0.7680.216/third_party/blink/renderer/core/editing/ime/input_method_controller.cc)에서 start/update는 `EventTarget::DispatchEvent`, end는 `EventDispatcher::DispatchScopedEvent`를 호출한다.
   - [EventTarget](https://github.com/chromium/chromium/blob/146.0.7680.216/third_party/blink/renderer/core/dom/events/event_target.cc)의 일반 네이티브 전달은 trusted를 true로 바꾼다. 반면 [scoped dispatcher](https://github.com/chromium/chromium/blob/146.0.7680.216/third_party/blink/renderer/core/dom/events/event_dispatcher.cc)와 [queue](https://github.com/chromium/chromium/blob/146.0.7680.216/third_party/blink/renderer/core/dom/events/scoped_event_queue.cc)는 해당 변경 없이 직접 전달해 [Event 생성자의 false 기본값](https://github.com/chromium/chromium/blob/146.0.7680.216/third_party/blink/renderer/core/dom/events/event.cc)이 남는다. 소스 경로와 실제 관측이 일치한다.
   - 따라서 **이 버전의 종료 이벤트에서 false라는 사실만으로 JS 합성 입력이라고 판단할 수 없다.** S01의 `ui/textarea-input`은 신뢰 플래그로 이벤트를 거르지 않고 종료 시 조합 상태를 해제하므로 이 플래그를 위한 제품 수정·가짜 trusted 처리·런타임 교체는 불필요하다.
   - 증거: [순수 OS IME 대조](validation/s01-ime-origin-native-2026-10-27.json), [프로토콜 대조](validation/s01-ime-origin-protocol-2026-10-27.json). 양쪽 `PROBE_PASS`와 종료 코드 0 확인.
2. **앱·입력기·자동화 원인 분리**
   - **앱:** 같은 실행 파일·그래프·블록에서 사용자 물리 키보드는 정상 `compositionstart/update/end` 및 `insertCompositionText`를 발생시켰다. 조합 중 상태 유지와 종료 시 해제, 정확한 Markdown 저장, 편집 전후·재시작 후 ID가 모두 확인됐다. S01이 입력받은 정상 한글을 자모로 변환하거나 손상시킨 증거는 없다.
   - **macOS 입력기:** 두벌식 입력 소스를 확인했고 사용자도 정상 입력을 확인했다. 순수 textarea 대조와 실제 앱의 물리 입력 모두 정상 조합한다. 입력기 설정·런타임 교체는 하지 않았다.
   - **자동화:** 단일 인스턴스·활성 창에서도 CUA `pressKey`가 자모를 일반 `insertText`로 보내는 실패가 재현됐다. renderer 이전의 Electron 키 이벤트부터 일반 keyDown이 관측되고, DOM keyCode는 229가 아닌 71/75 등이며 조합 이벤트는 0건이었다. 검색 입력칸에서도 동일했다. 반면 물리 입력에는 정상 조합 이벤트가 있다. 따라서 **자동화 키 전달이 IME 조합 경로를 거치지 않는 경우**를 직접 실패 경계로 식별했다. CUA 내부의 어떤 macOS 이벤트 API가 이를 유발하는지는 이 저장소에서 확인하지 않았으며 단정하지 않는다.
   - 별개로, 남아 있던 같은 bundle ID의 Electron 테스트 인스턴스 때문에 CUA가 현재 시험 대신 이전 데모 창을 선택한 것도 직접 관측했다. 임시 `s01-ui-*` 프로세스만 정리하고 중복 실행 방지를 추가했다. **중복 인스턴스만이 자모 분리의 원인이라고 결론 내리지 않는다.**

| B04 | Tags 탐색·결과 편집 | 전체 태그·직접 사용 수, 페이지별 outline, 전체 페이지/블록 하위 표시, 중복 제거, 결과에서 본문·태그 편집 | OG 쿼리/참조 결과 렌더러 활용한 전용 화면 | B03; 페이지 전체 포함 시 자식 결과 중복 제거 |
| B05 | 태그 이름 변경·삭제 | 이름 변경 전체 반영, 본문 보존 삭제, 미사용 태그 보존, 대소문자 중복 방지 | OG 페이지 이름 변경과 별개로 필요한 태그 계약 구현 | B03; 실패 복구와 undo 범위 결정 |
| B06 | Overview 바로가기 | 일반 Overview 페이지 열기·없으면 생성, 기존 내용 유지, 사이드바/단축키 | OG 일반 페이지·즐겨찾기 활용; 전용 진입점만 추가 가능 | 전용 사이드바가 필요한지 결정 |
| B07 | 오늘 저널 동적 임베딩 | `{{today-journal}}`, 자정·활성화·절전 복귀 후 오늘로 전환, 임베딩 안에서 편집 | OG 사용자 매크로·날짜 변수·페이지 임베딩 활용 가능성 확인 후 생명주기 보강 | 날짜 변수 존재만으로 자정 자동 전환을 보장하지 않음 |
| B08 | 임베딩 입력 별칭 | 독립 블록의 `![[페이지명]]`을 페이지 임베딩으로 해석 | OG 기본 `{{embed [[페이지]]}}` 재사용, 별칭 해석만 추가 후보 | 기존 입력 문법 보존 필요성; 이미지 링크 등과 충돌 확인 |
| B09 | 일반 Markdown 읽기 전용 outline | 그래프 밖 MD 열기, 제목·문단·목록을 표시 트리로 구성, 접기·집중 보기·원문 보기 | OG 그래프 편집과 분리된 읽기 전용 문서 화면 추가 | 원본 불변, 경로별 접힘 상태, 파일 변경 알림·명시적 다시 읽기 |
| B10 | MD 파일 즐겨찾기 | 절대 경로 즐겨찾기, 부모 경로 표시, 최근 등록순, 그래프 전환·재시작 후 유지 | OG 페이지 이름 즐겨찾기와 별도의 파일 목록 추가 | B09; 이동·삭제된 파일의 오류 처리 |
| B11 | External 문서 탐색 | `external/` 아래 MD 목록·경로 검색·읽기 전용 보기·수동 갱신 | 외부 문서 전용 데이터 경계 및 화면 추가 | B09 렌더러 재사용; OG 일반 그래프 인덱싱과 충돌 방지 |
| B12 | 외부 Markdown 임베딩 | `![[external/경로.md]]`와 embed 문법, 본문 안 outline·집중 보기·접기·새로고침 | 내부 페이지 임베딩과 구별되는 읽기 전용 파일 임베딩 추가 | B09/B11; 4MB 제한, 폴더 밖·심볼릭 링크 탈출 차단, 문서 안 매크로 실행 금지 |
| B13 | Codex 답변 스냅샷 가져오기 | 최종 답변만 MD로 추출, 출처 manifest, 새 임베딩 페이지 생성, 기존 결과 보존 | 기존 Python 스크립트의 OG 페이지 출력 형식 변경 | B11/B12 또는 OG 일반 페이지로 저장하는 대안 결정; 자동 동기화 아님 |
| B14 | 읽기 전용 Markdown 원문 창 | 원문 선택·전체 복사, 저장 전 현재 편집 내용 조회 | OG의 파일 보기와 동작 차이 확인 후 필요 시 추가 | B09의 원문 보기와 그래프의 미저장 내용 조회를 구분 |

### 기능별 중요한 계약

- B02 사용자 멘션
  - 블록 시작 또는 공백 뒤의 @만 자동완성; 이메일 내부에서는 열지 않는다.
  - 확정하지 않은 @문구는 일반 텍스트로 남긴다.
  - 동명의 일반 페이지를 자동으로 사용자 페이지로 전환하지 않는다.
- B03–B05 태그
  - 기존 본문 해시태그를 자동으로 새 태그 체계에 편입하지 않는 것이 bilog 계약이다.
  - 사용 수는 직접 지정만 계산한다. 결과의 하위 블록 노출 수와 다르다.
  - 결과에서 새 블록 생성·구조 변경은 제외하고 원본 페이지로 이동한다.
  - 기존 bilog 저장은 `tags.json` UUID + `bilog-tags` 메타데이터다. 이 저장 형식을 OG로 그대로 옮긴다는 결정은 아직 없다.
- B07 오늘 저널
  - 오늘 저널이 없을 때 조회만으로 불필요한 파일을 생성하지 않는다.
  - 날짜 전환 전 편집·한글 조합을 보존한다. 저장 실패 때 이전 날짜를 유지한다.
- B09–B12 문서 읽기
  - 표·코드·인용은 각각 표시 블록으로 취급한다. 일반 MD를 OG bullet 문서로 재저장하지 않는다.
  - 읽기 전용 체크박스를 눌러도 파일을 변경하지 않는다. BOM·줄바꿈·메타데이터 보존을 검수한다.
- B13 답변 추출
  - 질문·진행 설명·도구 결과·추론 기록과 subagent 세션을 제외한다.
  - 현재 로컬 세션 형식 의존성을 유지·검증하며 외부 서비스 연동을 새로 요구하지 않는다.

## 3. bilog에서 계획만 된 기능: OG에서 신규 구현할 후보

다음 항목은 bilog 구현물을 이식하는 일이 아니라, 기존 제품 명세의 요구사항을 OG 구조로 구현하는 일이다.

| ID | 기능 | 요구사항 | OG 활용 방향·검증 쟁점 |
| --- | --- | --- | --- |
| N01 | 전체 할 일 화면 | 모든 저널·페이지의 TODO/DOING/CONTINUE, 원본별 그룹·부모 경로, 같은 업무 중복 제거, 결과에서 내용·상태 편집·원본 이동 | 기존 task 쿼리·블록 렌더러·UUID 활용. bilog식 화면과 그룹 정책은 별도 구현 |
| N02 | 마감일 입력·정렬 | `YYYY-MM-DD TODO 내용` 입력, 날짜 보존 상태 전환, 그룹·업무를 마감일순 정렬, 무기한 뒤 배치 | OG DEADLINE 활용 가능. 입력 별칭만 제공할지 실제 저장 문법도 바꿀지 결정 |
| N03 | 완료 날짜와 당일 노출 | DONE 당일에는 표시하고 다음 날 숨김; 원본은 보존; 재시작 후 완료일 유지 | OG LOGBOOK 등과 구분해 일반 완료일의 안정적 저장 경로 확인. 반복 업무 완료 기록과 동일시하지 않음 |
| N04 | CONTINUE 연결 이월 | 오늘 저널 최초 생성 시 가장 최근 과거 저널의 미완료 CONTINUE만 연결, 부모 맥락·하위 항목 표시 | S01 문서 단위 참조 결정과 충돌하여 보류. 기존 블록 참조 활용안을 구현하지 않으며 별도 요구 재검토 필요 |
| N05 | 연결 업무 일관성·중복 방지 | 어느 연결 위치에서 수정해도 동일 업무 반영, 재시작 후 연결 유지, 재개방·실패 재시도 중복 방지 | N04 연결 이월과 함께 보류. S01 범위에서 연결 업무를 암묵적으로 구현하지 않음 |

### 기존 명세에서 유지할 세부 조건

- 부모·자식의 완료 상태는 독립적이다.
- 이월 대상은 과거 모든 저널이 아니라 가장 최근의 기존 과거 저널 하나다.
- 오늘 저널 재개방과 과거·미래 저널 생성은 이월을 다시 실행하지 않는다.
- 전체 할 일의 원본 이동·그룹은 최초 작성 위치 기준이다.
- 정렬은 화면 표시만 바꾸고 원본 bullet 순서를 바꾸지 않는다.
- 완료 날짜 없는 기존 DONE 처리, 같은 마감일 동률 정렬, 완료 항목 배치는 미확정이다.

## 4. OG 기본 기능으로 재사용할 항목

아래는 독립 이식 작업으로 잡지 않는다. bilog와 정확한 키·경계 동작이 같다는 뜻은 아니므로 대표 사용 시나리오를 검수한다.

| 기능 | 기본 방침 | 확인할 차이 |
| --- | --- | --- |
| 블록 작성·분할·들여쓰기·순서 이동·접기·집중 보기 | OG 아웃라이너 유지 | Enter/Backspace 경계, 한글 조합, 다중 선택, undo/redo |
| 저널과 일반 페이지·검색·백링크 | OG 기본 기능 활용 | 저널 연속 보기, 오늘 진입, 목록 복귀 위치, 검색·정렬 UX |
| 내부 문서 임베딩 | OG 페이지 임베딩 기반을 파일 이름 참조에 맞게 조정 | 블록 임베딩 제외; 순환 참조·없는 대상·포커스·undo 검수 |
| 페이지 즐겨찾기 | OG `:favorites` 활용 | B10의 임의 MD 경로 즐겨찾기와 혼동하지 않음 |
| 태그·페이지 속성·task 쿼리 | 데이터·조회 기반으로 활용 | bilog의 분리 배지·미사용 태그 보존·결과 계약은 B03–B05 |
| 자동 저장·외부 변경 처리 | OG 저장 흐름 활용, S01 ID 분리를 위한 저장 경계 수정 | 문서·외부 ID 메타데이터 일관성, 충돌·재시작·외부 변경 검수 |
| 글자 크기·단축키 | OG 설정을 먼저 활용 | 본문만 확대 vs 앱 전체 확대, bilog 키와 OG 기본 키 충돌 |

## 5. 구현 전에 결정할 사항

- D01 — 태그 저장: OG 페이지 참조/속성을 활용할지, UUID 레지스트리를 유지할지. 기존 해시태그와 새 태그의 분리 계약도 함께 정한다.
- D02 — 사용자 속성: bilog YAML frontmatter 유지 vs OG 페이지 속성으로 변환.
- D03 — 마감일: bilog식 입력만 지원하고 OG DEADLINE으로 저장할지, bilog식 원문도 유지할지.
- D04 — 문서 참조만 지원하는 것으로 확정. N04/N05 연결 업무는 이 결정과 충돌하여 보류하고 별도 재검토한다.
- D05 — 읽기 전용 문서 범위: B09 독립 파일·B11 External 목록·B12 임베딩을 모두 첫 버전에 포함할지.
- D06 — 단축키: Overview `Cmd+Shift+O`, 파일 열기 `Cmd+O`, 오늘 `Cmd+T` 등은 OG와 충돌 확인 후 배정.
- D07 — 새 그래프에서 시작하는 것으로 확정. 기존 문서 가져오기는 후속 작업이다.
- D09 — `logseq/identity.sqlite` ID 캐시, 외부 변경 문서의 블록 ID 전체 재생성, 캐시 삭제·손상 시 알림 후 자동 재생성으로 확정. 충돌은 `logseq/conflicts/`에 양쪽 MD를 보관하고 버전을 선택하며 사용자 삭제 전까지 유지한다. 상세 SQLite 스키마·저장 실패 복구는 S01 구현 계획에서 검증한다.
- D08 — UI 일치 범위: bilog 화면 배치를 그대로 재현할지, 기능만 옮기고 OG UI를 사용할지.

## 6. 데이터 이전은 별도 작업

실제 노트 이전이 필요할 경우에만 진행한다. 현재는 이전을 실행하지 않았다.

- 페이지 UUID 파일명과 실제 제목, 저널 날짜 형식, 사용자 frontmatter 변환.
- `tags.json` 이름/UUID와 `bilog-tags` 지정 관계 변환.
- `@[[사용자]]`, `![[페이지]]`, `{{today-journal}}`, external 경로 처리.
- `.native-logseq/identities`의 재생성 가능한 ID를 OG 영속 블록 ID로 오인하지 않기.
- 원본 사본에서 변환 후 본문·계층·링크·태그 수와 외부 파일 해시 비교.
- 재실행해도 중복하지 않는 변환 기록과 원본 백업.

## 7. 제안하는 구현 순서 — 미확정

기존 편집기와 저장 경로를 최대한 보존하며 작은 변경부터 검증하는 순서다. 사용자 우선순위 확정 전에는 작업 순서를 고정하지 않는다.

1. OG 기본 편집·한글·저장·재시작 사용 검수, S01/D09 저장 구조 설계·검증. D01–D08 중 첫 기능에 필요한 결정.
2. B06 Overview, B01 CONTINUE, B02 사용자 멘션.
3. N01 전체 할 일의 기본 조회·편집 → N02/N03 날짜·완료 정책.
4. N04/N05는 문서 단위 참조 정책과 충돌하여 보류. 별도 요구 재검토 전 구현하지 않는다.
5. B03–B05 태그 UI와 결과 화면.
6. B09 → B10/B11 → B12 → B13 문서 읽기·답변 가져오기 묶음.
7. B07/B08/B14와 탐색·단축키 차이 보완.

문서 읽기와 Codex 답변 활용이 우선이면 6번 묶음을 앞당길 수 있다.

## 8. 최소 완료 기준

- S01: 위 V01–V14 검증 시나리오를 충족한다. Markdown 원본, 일반 경로 SQLite ID 캐시, 파일 이름 기반 문서 참조 및 사용자 선택에 따른 충돌 복구를 준수한다.

- B01: 모든 입력 경로에서 CONTINUE 인식·전환·검색·저장이 일치하고 기존 OG 상태를 손상하지 않는다.
- B02: 사용자 생성·선택·백링크·이메일 제외·한글 조합을 확인한다.
- B03–B05: 페이지 전체/부모 블록/자식 블록 중복 제거와 직접 사용 수를 별도로 확인한다.
- B09–B12: 읽기·접기·집중 보기·새로고침·재시작 후 원본 파일 바이트가 불변이다.
- B13: 최종 답변만 내보내고 원본 세션과 기존 결과를 변경하지 않는다.
