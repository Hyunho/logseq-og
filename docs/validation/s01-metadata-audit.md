# S01 Markdown 메타데이터 분리 — 2026-10-28

S01(`:s01/enabled? true`) Markdown 그래프에서 앱이 생성하는 기능 데이터를 Markdown 원문과 분리했다. 일반 OG 그래프와 Org의 저장 방식, 사용자 작성 속성 API는 유지한다.

## 저장 경계

- 사용자 원문
  - `:block/content`에는 사용자 속성을 유지한다. 앱 속성은 DB의 유효 속성에 겹쳐서 기능에 제공한다.
  - 앱이 변경하기 전 사용자 값과 출처를 `:block/app-metadata`에 기록한다. 같은 이름의 `query-sort-by`, `card-*`, 배경색 등이 원문에 있어도 삭제하거나 덮어쓰지 않는다.
  - 공개 `set-block-property!` API는 사용자 작성 경로다. 사용자가 직접 바꾸는 키는 앱 소유에서 해제하고 MD에 기록한다. 앱의 메뉴·기능은 별도의 `set-app-property!` 경로를 사용한다.
  - 코드 블록의 속성·LOGBOOK 예시는 데이터로 유지한다. 시간 기록의 분리에는 AST의 UTF-8 위치를 사용한다.
- 별도 저장소
  - `logseq/metadata.sqlite`: 기능 값, 사용자 원래 값, 시간 기록, 블록 식별 스냅샷을 보관하는 영속 저장소다. ID 캐시와 별개이며 자동 초기화하지 않는다.
  - `logseq/identity.sqlite`: 기존 ID 캐시 및 접힘 상태 저장소다. 접힘 상태는 기존 분리 구현을 유지한다.
  - 기능 변경은 DataScript 트랜잭션에 포함되므로 undo/redo에 따라 별도 저장 값도 되돌아간다. 본문 투영이 같으면 MD 쓰기와 dirty 판정을 생략한다.
  - 저장 실패 시 오류를 표시하고 다음 편집에서 재시도한다. 실패한 메타데이터를 원문에 대신 삽입하지 않는다.
- 복원
  - 파싱 및 시작 시 별도 저장 값을 적용한다. 오래된 renderer 캐시보다 별도 저장소가 우선한다.
  - ID 캐시 삭제·손상 후 동일한 문서는 기능 기록과 연결된 ID를 복원한다. 파일 이동도 구분하며, 복사본에 원본 ID를 공유하지 않는다.
  - 외부 편집 시 유일하게 일치하는 블록 및 나머지 위치가 동일한 단일 블록 편집은 기록을 연결한다. 복수 블록의 모호한 대체는 임의로 연결하지 않으며, 기존 기록은 별도 저장소에 남는다.

## 분리한 기록 경로

| 데이터 | 처리 |
| --- | --- |
| 접힘 상태 | 기존 별도 저장 유지. 접기·펼치기·undo가 MD를 변경하지 않음 |
| 쿼리 표/목록, 표시 열, 정렬 기준·방향 | 쿼리 컴포넌트와 설정 핸들러를 앱 속성 저장으로 전환 |
| 배경색, 번호 목록, heading 표시 플래그 | 메뉴·목록 상속·heading 변경을 앱 속성 저장으로 전환. 실제 Markdown heading 문법은 본문으로 유지 |
| 템플릿 이름·부모 포함 설정 | 앱 메뉴의 설정은 별도 저장. 사용자 원문/공개 API 속성은 유지 |
| 카드 간격·반복 수·점수·다음 학습일·마지막 학습일·난이도 | SRS 평가·초기화·일정 변경을 별도 저장. 기능은 유효 DB 속성을 계속 읽음 |
| CLOCK 및 반복 작업 완료 이력 | 앱이 생성한 LOGBOOK만 별도 저장. TODO/DOING/DONE, 예정일·마감일 변경은 원문에 반영. 사용자 기존 LOGBOOK은 원문으로 보존 |
| 기존 PDF 하이라이트 색·스탬프 | 수정 시 별도 저장. 기존 S01의 신규 블록 참조 생성 제한은 유지 |
| Roam 가져오기 자동 ID | 생성 ID를 out-of-band 속성으로 전달하고 파싱 완료 후 별도 연결. 파일에는 생성 `id::`를 쓰지 않음 |
| 일반 블록 참조 자동 ID | 기존 serializer·복사·watcher·PDF 차단 및 참조 선택·Alt 드래그 차단 유지 |
| 파서 유래 macro 속성 | 원문에 없는 `logseq.macro-name`/`logseq.macro-arguments`의 편집 중 재삽입 방지 |
| 파일명에서 유도되는 자동 title | S01에서 불필요한 자동 title 헤더를 만들지 않음. 명시적으로 작성/가져온 제목은 유지 |
| DB 생성·수정 시각 | DB 속성으로 유지하며 MD 속성을 새로 만들지 않음 |

## 사용자 데이터 보존 정책

이미 존재하는 속성의 이름만으로 앱 생성 여부를 판정할 수 없다. 따라서 출처 기록이 없는 기존 속성은 사용자 원문으로 취급한다. 앱에서 동일한 설정을 이후 변경하더라도 원문의 기존 값은 보존하고 새 유효 값만 별도 저장한다. 기존 파일을 일괄 정리하거나 출처 불명 속성을 삭제하지 않는다.

`title`, tags/aliases, 직접 작성한 표 설정, 플러그인/공개 API에 명시적으로 전달한 속성은 원문이다. 사용자 데이터 보존과 앱 내부 데이터 분리의 기준은 속성 이름이 아니라 쓰기 경로다.

## 패키지 빌드 및 bilog2 실사용 검증 — 2026-10-28

개발 서버가 없는 macOS arm64 패키지 앱을 다시 빌드하고 bilog2에서 검증했다. 아래 결과는 이날의 실제 그래프와 패키지에 대한 확인이며, 모든 향후 편집이나 임의의 플러그인 동작을 보장하는 의미는 아니다.

- 빌드 및 실행
  - gulp 정적 자산, app/electron release 빌드 후 `scripts/package-macos.cjs`로 패키징했다.
  - 별도 release 디렉터리를 사용하는 경우 패키징 전 자산 검사도 해당 디렉터리의 `electron.js`, `js/main.js`를 확인하도록 수정했다.
  - 패키지 서명 검사 및 release 자산과 패키지 자산의 해시 일치를 확인했다.
- 초기 그래프 점검
  - `:s01/enabled? true`, `logseq/identity.sqlite`, `logseq/metadata.sqlite`를 확인했다.
  - 사용자 문서 MD 4개에서 자동 ID·접힘·쿼리·학습 설정 속성이 발견되지 않았다.
  - 오늘 저널에 기존 LOGBOOK 1건이 남아 있었다. 재빌드 전 저장본과 일치하는 기존 기록으로, 출처 불명 원문 보존 정책에 따라 자동 삭제되지 않은 항목이었다.
- 사용자 요청에 따른 기존 LOGBOOK 이관
  - 앱을 종료하고 원문과 두 SQLite 저장소를 그래프 내부 `logseq/backups/logbook-migration-20261028-150456/`에 백업했다.
  - 시간 기록을 기존 블록 ID의 `metadata.sqlite` 항목으로 옮기고, MD에서는 LOGBOOK 구간만 제거했다. 사용자 작성 본문과 속성은 유지했다.
  - 변경된 원문에 맞춰 ID 저장소와 영속 식별 스냅샷을 갱신했다. 두 SQLite 저장소의 `quick_check`는 모두 `ok`였다.
  - 이 작업은 해당 1건에 대해 명시적으로 요청받은 이관이며, 앱의 일반적인 기존 원문 보존 정책은 바꾸지 않았다.

### 재실행·편집·저장 검증

실제 패키지 앱을 Playwright Electron으로 실행하고 공개 API로 복원된 값을 읽었다. 편집은 화면의 textarea에서 수행하고 Escape로 저장했으며, 화면 변경뿐 아니라 실제 파일 저장 완료까지 기다렸다.

| 확인 항목 | 결과 |
| --- | --- |
| 초기 재실행 후 기존 시간 기록 | 별도 저장소의 7개 블록 모두 앱의 유효 본문에서 일치. 이관한 기록의 `1s` 화면 표시도 확인 |
| 초기 재실행 후 접힘 상태 | 저장된 2건 모두 일치. 이관한 기록의 블록도 접힌 상태로 표시 |
| 실제 편집·저장 | 이관한 블록의 첫 줄에 임시 문구를 추가해 저장. 시간 기록과 접힘 상태 유지, MD에 내부 메타데이터 재삽입 없음 |
| 편집 원복 | 같은 편집기에서 원래 내용으로 복원하고 파일 저장 완료 확인 |
| 접기·펼치기 | 저장된 두 상태를 각각 반대로 바꾼 뒤 원래 상태로 복원. 동작 중 MD 바이트 변경 없음 |
| 다시 재실행 | 7개 블록의 시간 기록과 접힘 상태 2건 모두 유지 |
| 최종 원문 | MD 4개 모두 검증 시작 전과 바이트 단위로 일치. LOGBOOK 0건 |
| 최종 별도 저장소 | 기존 시간 기록 값과 접힘 상태 일치, 두 SQLite 무결성 검사 정상 |

검증 후 앱을 다시 열었다. 익명화한 결과 요약은 [bilog2-metadata-verification.json](bilog2-metadata-verification.json)에 보관한다. 그래프 원문, 실제 시간 기록, SQLite 및 복구 백업은 저장소에 포함하지 않는다. 임시 실사용 검증 스크립트도 다른 환경에서 실제 그래프를 자동 수정하지 않도록 배포 테스트에 포함하지 않았다. 반복 가능한 격리 그래프 검증은 `electron-metadata.cjs`와 `electron-collapsed.cjs`를 사용한다.

## 커밋 범위

이 변경은 메타데이터 분리에 필요한 미커밋 S01 기반도 함께 포함한다. ID 캐시·문서 식별, 원문 보존 저장·충돌 처리, 파서·watcher 연동 및 해당 기능의 회귀 테스트가 그 기반이다. 기존 S01의 블록 참조 제한과 사용자 원문 정책은 유지한다. macOS 개발 실행의 별도 deeplink 수정과 기존 IME 검증 자료는 이 메타데이터 커밋에서 제외한다.
